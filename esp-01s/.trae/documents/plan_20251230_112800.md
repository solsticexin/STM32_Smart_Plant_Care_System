# 智能植物护理系统后端重写计划

## 1. 项目概述

### 1.1 项目目标
重写整个后端系统，使其支持ESP-01S在WiFi模式下主动创建热点，供手机连接并访问控制网页，严格遵循通信协议中定义的数据格式、指令集和交互流程。

### 1.2 核心需求
- ESP-01S创建WiFi热点，SSID为"智能盆栽养护检测系统"，密码为1-8位字符
- 实现与STM32的串口通信，遵循通信协议
- 提供Web服务器，支持静态页面访问和WebSocket实时通信
- 实现前后端数据交互，确保数据格式准确无误

## 2. 技术栈

- 开发框架：ESP8266 Arduino Core
- Web服务器：ESP8266WebServer
- WebSocket：WebSockets
- 串口通信：HardwareSerial
- 数据处理：自定义协议解析器

## 4. 详细设计

### 4.1 协议解析器设计

**帧结构处理**：
- SOF检测：寻找0xAA起始标志
- 长度解析：根据LEN字段确定帧长度
- 类型解析：确定消息类型
- TLV解析：解析标签、长度和值
- CRC校验：验证数据完整性

**消息类型处理**：
- 0x01：传感器数据上报
- 0x02：执行器状态反馈
- 0x10：控制命令
- 0x11：命令确认
- 0x20：心跳

### 4.2 串口通信设计

**接收流程**：
1. 从串口读取原始数据
2. 传递给协议解析器解析
3. 根据消息类型分发处理
4. 通过WebSocket发送给前端

**发送流程**：
1. 接收前端命令
2. 构建协议帧
3. 发送到串口
4. 处理命令确认

### 4.3 Web服务器设计

**静态页面**：
- 托管前端HTML、CSS和JavaScript文件
- 支持直接访问

**WebSocket**：
- 实时数据推送
- 命令接收和发送
- 连接状态管理

**HTTP API**：
- 提供设备状态查询
- 支持配置更新

### 4.4 WiFi热点设计

**热点创建**：
- 使用指定SSID："智能盆栽养护检测系统"
- 支持1-8位密码
- 配置合理的信道和加密方式

**状态管理**：
- 监测连接状态
- 自动重试机制
- IP地址管理

## 6. 通信流程

### 6.1 传感器数据上报
1. STM32发送传感器数据帧
2. ESP-01S解析帧数据
3. 通过WebSocket推送给前端
4. 前端更新UI显示

### 6.2 控制命令发送
1. 前端发送控制命令
2. WebSocket接收命令
3. 构建协议帧
4. 发送到STM32
5. 接收命令确认
6. 通知前端命令结果

### 6.3 执行器状态反馈
1. STM32发送执行器状态帧
2. ESP-01S解析帧数据
3. 通过WebSocket推送给前端
4. 前端更新执行器状态显示

## 7. 错误处理

- 协议解析错误：丢弃无效帧
- WebSocket连接错误：自动重连
