# 基于新通信协议的前端重构计划

## 1. 项目分析

### 1.1 新通信协议概述
- 基于UART的二进制协议，采用定长帧头+变长载荷(TLV)+校验尾设计
- 帧结构：SOF(0xAA) + LEN + TYPE + Payload(TLV) + CRC
- 支持传感器数据上报、执行器状态反馈、控制命令和命令确认等消息类型

### 1.2 当前前端实现
- 基于HTTP轮询的JSON接口
- 主要功能：网络状态显示、环境数据展示、执行器控制、阈值设置、消息日志
- 需完全移除旧协议代码

## 2. 重构目标

1. 彻底移除所有旧协议实现代码
2. 实现新协议的完整解析和构建功能
3. 重新设计前端架构，确保与新协议兼容
4. 保留原有UI结构，更新数据绑定逻辑
5. 提供完整的功能测试报告

## 3. 架构设计

### 3.1 核心模块设计

#### 3.1.1 协议解析器 (ProtocolParser)
- 帧检测与同步：基于SOF(0xAA)的帧起始检测
- CRC计算：实现异或校验算法
- 帧解析：将二进制数据解析为结构化消息
- 帧构建：将命令转换为二进制帧
- TLV处理：解析和构建TLV格式数据

#### 3.1.2 状态管理器 (StateManager)
- 传感器数据管理：存储和更新传感器数据
- 执行器状态管理：存储和更新执行器状态
- 命令队列管理：处理命令发送和确认
- 事件发布订阅：提供状态变更通知机制

#### 3.1.3 通信管理器 (CommunicationManager)
- 数据接收处理：从串口/网络接收二进制数据
- 数据发送处理：发送构建好的二进制帧
- 连接状态管理：处理连接建立和断开

### 3.2 数据流设计

1. **数据接收流程**：
   - 通信管理器接收二进制数据
   - 协议解析器解析数据为结构化消息
   - 状态管理器更新内部状态
   - 触发UI更新事件

2. **命令发送流程**：
   - UI生成命令请求
   - 协议解析器构建二进制帧
   - 通信管理器发送帧数据
   - 状态管理器跟踪命令状态
   - 接收命令确认并更新状态
